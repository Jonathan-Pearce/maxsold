# Data Directory

This directory contains all data files for the project, organized by processing stage.

## Directory Structure

```
data/
├── external/   <- Data from third party sources
├── interim/    <- Intermediate data that has been transformed
├── processed/  <- The final, canonical data sets for modeling
└── raw/        <- The original, immutable data dump
```

## Subdirectories

### raw/
The original, immutable data dump. This is where scraped data, downloaded images, and any other raw input data should be stored. **Never edit files in this directory.**

Examples:
- Scraped auction data
- Downloaded images
- API responses

### interim/
Intermediate data that has been transformed. This includes partially processed data that is not yet ready for modeling.

Examples:
- Extracted features (previously in `data/engineered/`)
- Cleaned but not yet finalized datasets
- Intermediate feature representations

### processed/
The final, canonical data sets for modeling. This is the data that is actually used for model training and prediction.

Examples:
- Final training datasets
- Final test datasets
- Model-ready feature matrices

### external/
Data from third party sources. This could include reference datasets, benchmarks, or any data not generated by this project's scripts.

Examples:
- External market data
- Reference pricing information
- Geographic data

## Data Versioning

Consider using tools like DVC (Data Version Control) or similar to version control large data files that shouldn't be stored in Git.

## Best Practices

1. **Never edit raw data**: All transformations should be done in code
2. **Document data sources**: Keep a log of where data came from
3. **Use consistent naming**: Follow naming conventions for easier navigation
4. **Keep interim data**: Saves computation time when re-running pipelines
5. **Backup important data**: Don't rely solely on local storage
